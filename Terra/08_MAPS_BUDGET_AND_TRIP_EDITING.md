# 08 — Maps, budgets, comparison, trip editing and personalization foundation

## Map implementation

Use MapLibre GL JS with an offline-first map strategy. Do not depend on public OSM tile servers or CDN at runtime; follow tile/source usage terms. For first release use a local licensed simplified India/region GeoJSON basemap plus canonical coordinates and labeled pins. If feasible, build a compact regional PMTiles/vector-tile package with local style/fonts/sprites and attribution; package or document reproducible download. Online tiles are optional, explicit configuration. Always show OpenStreetMap attribution when using OSM-derived data. If WebGL unavailable, list view and accessible SVG/static coordinate overview remain usable. Do not represent straight lines as actual roads. Pins reflect real canonical coordinates; missing coords are omitted with a count/warning. Synchronize selected card and map marker, fit valid bounds, cluster if needed, avoid geolocation permission unless user explicitly asks. A map is not a routing engine.

Routing interface returns `{distance_km, duration_minutes, geometry, provider, computed_at, verification_status}`. `offline`: haversine distance labeled straight-line; no exact route/travel time unless bundled verified road data. Optional `osrm` adapter calls configured trusted host with timeout, cache, rate limit and explicit network toggle; no arbitrary user endpoint, no SLA promise. Validate road snapping and response geometry; fail gracefully. Group nearby POIs, leave transit buffers, use measured route duration only when provider supplied it. Show dashed approximate connectors differently from road geometry. Respect closures and permits unknown. Weather optional Open-Meteo with historical/forecast distinction, time range, timestamps and offline cached normals.

## Budget service

Money as integer INR (or paise consistently); reject negative/invalid amounts, low > high, mismatched currency. Normalize traveler count, rooms, nights, cost basis, origin and season. Accommodation total = rooms × nights × per-room nightly range; food = travelers × days × per-person range; activity = per-person or group basis × actual selection; transport from origin with roundtrip status; local travel by documented basis; contingency explicit. Avoid double counting included meals/transfers. Do not assume hotel nights always equal duration minus one if dates/preferences say otherwise. Unknown fields remain unknown, never substituted zero. Return known subtotal low/high, unknown categories, complete flag, estimate dates and source refs, budget status `within_estimate|over|uncertain|incomplete`. Compare total with user budget only when compatible. Actual price never implied. Test boundary amounts, single traveler vs family, 1-day trip, multi-room, unknown transport, different origins and currency.

UI: range-based breakdown donut/bar using existing Recharts, category details and provenance; sliders/selectors for documented cost scenarios, instant deterministic recalculation, pending edits distinguish draft vs saved. If data missing show coverage gap rather than fake values. Backend remains authority and recalculates before save. Budget status accessible by text/icon, not color only. Export includes estimates disclaimer.

## Comparison and saved places

Compare 2–3 destination IDs in a stable side-by-side view. Dimensions: geography, source-supported interests, climate period, travel/cost estimate range if comparable, attractions, evidence quality/coverage and unknowns. No opaque LLM winner or percentage match. User can emphasize preferences and see evidence; do not compare costs with different origins/durations/party basis. Save/unsave idempotent and owner-only, with optimistic UI rollback on error, list search/filter, compare and plan. Avoid redundant saved state in localStorage.

## Editable itinerary and replan

Use a typed patch with expected trip version. Reorder within or across days via accessible keyboard controls and optional drag/drop. Replace activities from canonical candidates; user-authored activities allowed and marked user input. Validate time overlap, travel gaps, citations and costs before commit. A partial replan request locks untouched day IDs and user-locked items, passes validation feedback and evidence to agent, replaces only requested portion, recomputes whole trip constraints and stores new version with parent reference. Failed/cancelled run does not mutate prior trip; display validation errors. Restore creates a new version referencing prior one, not destructive rollback. Conflict (409) prompts reload or explicit reapply. Print/export HTML/PDF via browser print or documented existing export; no fake public share link. Existing full replan still works.

## Acceptance

Offline map renders without network and correct attribution; list fallback works; selection synced and missing coords handled. Optional routing timeout yields honest fallback. Budget sums and ranges match backend; missing items visibly incomplete. Compare saved places and cross-user ownership tested. E2E reorder, replace, partial replan, invalid overlap and conflict, version history/restore and print; existing seeded plans and old versions still load. No unverified route times/prices.
